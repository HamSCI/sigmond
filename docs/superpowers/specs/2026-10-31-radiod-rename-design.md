# Renaming a radiod instance: `smd admin radiod rename`

Date: 2026-10-31. Author: Rob Robinett's Claude session, from Rob's request on
AI6VN-PM. Status: design, awaiting builder check and plan.

## 1. Intent

An operator names a radiod instance once, at `smd config init radiod`, and the
name becomes the multicast status name (`<id>-status.local`) every client
binds to. When the name is wrong, there is no way back short of re-running
bring-up. On AI6VN-PM today the running radiod on the TCI-530 Omni is called
`AI6VN` and the new, inactive one on the second card is called `omni`; Rob
wants `omni` -> `se` and then `AI6VN` -> `omni`, with the antenna description
changed in the same action. The KFS station (design 2026-10-30) will name its
four radiods by antenna (`se`, `omni`, `nw`, `sw`) and will make the same
mistakes.

## 2. Goals

- G1 `smd admin radiod rename <old> <new> [--description TEXT]` renames one
  local radiod instance in one step, including its status name, and leaves
  every client listening to it still listening to it.
- G2 `smd admin radiod describe <id> TEXT` changes only the antenna
  description.
- G3 Both show the full plan with `--dry-run` and write nothing on refusal.
- G4 A one-radiod station is handled the same way; nothing in this design
  depends on two instances.

Non-goals: renaming client instances (reporter ids such as `psk-recorder@AI6VN`
are reporter ids, not radiod ids, even when the strings coincide); moving a
client between radiods; renaming remote radiods (another host's); renaming
historical data (sink rows, logs, spool directories keep the old name).

Anti-goals: a half-renamed station (conf moved, clients still on the old
name); a rename that silently changes which radiod gets the plain
`ka9q-web.service` on port 8081 without saying so; a rename while a manual
RX888 hold names the old unit.

## 3. Constraints

- Stdlib only; root-only actions self-elevate through `_need_root`; pure
  logic in `lib/sigmond/`, tested on fake trees without root.
- The radiod id stays case-sensitive and must match `[A-Za-z0-9_.-]+` (what
  `timing_judge.py` already accepts and what systemd needs no escaping for).
- The status name follows the id: after the rename the conf's `[global]
  status` is `<new>-status.local` whatever it was before, and every file that
  held the OLD status string (exact, whole token) gets the new one.
- Edits are text edits of the operator's files, never re-renders: comments,
  ordering and hand edits survive. Each file is written atomically (temp +
  `os.replace`, mode and owner preserved).
- Nothing is written until the whole plan has been computed and every
  refusal has passed.

## 4. What a rename touches (from the 2026-10-31 inventory)

Things the inventory says are NOT keyed by id or status and need no change:
the RAC relay (ports only), the template-level `radiod@.service.d` drop-ins
(`%i`), the watchdog and arrival units (globs), `sdr-events.jsonl` (free text).

## 5. The rename, step by step

Verb: `smd admin radiod rename <old> <new> [--description TEXT] [--dry-run] [--yes]`.

1. **Plan.** Build the complete list of edits (path, before, after), moves
   (from, to) and unit operations from the current files. Pure function,
   `radiod_rename.plan(old, new, description, root=Path('/'))`.
2. **Refuse** (rc 1, nothing written) when: `<old>` has no conf; `<new>` already
   has a conf, a coordination table, a drop-in dir, or an enabled unit; `<new>`
   fails the id pattern; `sdr-hold.json` names `radiod@<old>.service`; `<old>`
   is a remote radiod (`host != localhost`) or a sig_gen/bootstrap stub id.
3. **Show** the plan: every file touched with a one-line diff summary, every
   unit stopped and started, the ka9q-web consequence (which radiod gets
   port 8081 after sorting), and the "history stays under the old name" list.
   `--dry-run` stops here, rc 0.
4. **Confirm** unless `--yes` (the plan restarts decoders).
5. **Stop**, under the lifecycle lock, in this order: the clients whose
   config names the old status (their units, found through `lifecycle`:
   `psk-recorder@*`, `wspr-recorder@*`, `meteor-scatter@*`, the hf-timestd
   units), the ka9q-web unit serving the old status, `radiod@<old>`. Disable
   `radiod@<old>`.
6. **Write** every planned edit and move, atomically per file. On any
   failure after the first write: stop, print exactly which files were
   written, exit 4, do not start anything (the operator finishes by hand with
   the printed list; this is the anti-goal case and must be loud).
7. **Regenerate** derived files: `coordination.env` via `render_env`; the
   ka9q-web units via the existing writer; `systemctl daemon-reload`.
8. **Start** `radiod@<new>` (enable), then the ka9q-web unit, then the
   clients stopped in step 5, in lifecycle order.
9. **Report**: the moved conf, the files edited (count per directory), the
   units restarted, the ka9q-web port map, the history note, and the uploader
   note ("spots decoded after the rename are filed under receiver `<new>`
   on wsprdaemon; set `receiver_override` in pipelines.toml to keep
   `<old>`"). End with the `smd admin sdr list` tables.

`smd admin radiod describe <id> TEXT [--dry-run] [--yes]`: steps 1 to 4 with a
one-edit plan (the `description =` line in the hardware section), then
restart `radiod@<id>` only. No client restarts; the description only surfaces
in radiod's status stream.

## 6. Exit codes

0 done; 1 refused (nothing written); 2 operator declined at the prompt; 4
failed mid-write or `systemctl daemon-reload` failed (written list printed,
nothing started); 5 renamed, but a unit that had been running did not start
(`renamed, but these units did not start: <units>`; describe: `description set,
but these units did not start: <unit>`).

## 7. Observability

Every edit is logged one line per file to stdout and to the journal (the
`sdr_events` record is not used; this is not an SDR event). A final
`smd admin sdr list` proves the conf and serials are intact.

## 8. Rollout and test

Pure plan tests on a fake root containing exactly AI6VN-PM's files as of
2026-10-31 (the 12 files that name `AI6VN-status.local`, the coordination
table keyed by status name, the second table keyed by id, the drop-in dir, a
consumer drop-in, a `clients/*.sources.toml`), asserting the full edit list
and the refusals. Apply tests on a tmp tree with a fake `systemctl` recorder
asserting stop/start order and the exit-4 path. First live run: AI6VN-PM,
`omni` -> `se` (inactive instance; nothing to restart but radiod itself),
then `AI6VN` -> `omni` (running, with clients).

## 9. My calls (Rob to overrule)

- The status name always follows the new id. A station that had hand-set a
  status unlike `<id>-status.local` loses that, and the plan shows it.
- History directories are not moved. Moving psk-recorder's state or
  wspr-recorder's shm dirs while units are stopped is possible but buys
  nothing the clients do not recreate, and a failed move is worse than a
  stale directory.
- The ka9q-web units are regenerated by the existing writer rather than
  edited, because the plain-unit choice is a sort-order rule that lives
  there. The plan prints the resulting port map so a changed 8081 holder is
  never a surprise (on AI6VN-PM, `omni` < `se`, so the renamed running radiod
  keeps 8081).
- `pipelines.toml`'s `decoding_software` label is rewritten; the wsprdaemon
  receiver name is a consequence of the status and is reported, not pinned.
- A `[[radiod.fragment]]` body that embeds the old status is rewritten like
  any other file; no client declares fragments today.

## 10. Builder-check answers (my calls, 2026-10-31)

1. **Prior run state is restored, never upgraded.** Before step 5 the plan
   records `is-active` and `is-enabled` for `radiod@<old>`, its ka9q-web
   unit and every client it will stop. Step 8 starts and enables only what
   was active and enabled before. An instance the operator had parked stays
   parked after the rename (on AI6VN-PM, `omni` -> `se` leaves `se`
   inactive; `smd apply` starts it later). The report says so.
2. **ka9q-web: the rename owns the cleanup around the writer.** It computes
   the ka9q-web targets before and after (same rule as `_ka9q_web_targets`),
   then after the writer runs it stops, disables and removes every ka9q-web
   unit and env that is no longer a target, and restarts a bystander whose
   unit changed form (plain <-> templated) or status. The plan prints the
   before/after port map; a changed 8081 holder is shown in the plan, not
   discovered.
3. **Files are found by scanning, within known directories.** `plan()`
   scans `/etc/sigmond`, `/etc/radio`, `/etc/hs-uploader` and `/etc/<name>/`
   for every installed client (catalog + topology) for the exact old status
   token and the exact `radiod@<old>` unit token, whole-token matches only
   (quoted string, `radiod:<status>`, `After=`, `-m <status>`, table
   header), and edits every hit. Hits elsewhere under `/etc` or `/var/lib`
   are reported as "not edited". The test fixture's expectation is the scan
   result on AI6VN-PM's files.
4. **Clients to stop and restart:** the union of clients whose config
   holds the old status and clients coordination binds to the old key
   through `[[clients.*]] radiod_id`.
5. **`--description` with no `description =` line** inserts it as the last
   key of the hardware section; no hardware section at all is a refusal.
6. **A conf without `[global] status`** is treated as `<old>-status.local`
   for the scan and gets a `status = <new>-status.local` line added under
   `[global]`. A status unlike `<old>-status.local` is still rewritten
   (the scan token is whatever the conf says).
